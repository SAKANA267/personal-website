# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

A **faithful port** of an older site (`nihonggo_web_learning`) from "raw HTML/CSS/JS + PHP/MySQL + Node WebSocket" to "Vue 3 + TypeScript SPA + Node/Express + MySQL + ws". Despite the legacy directory name, this is SAKANA's personal website (home / online chat / question bank / dev log / blog / share / login+signup / data masking / value tracking / site-wide search) — it contains **no** Japanese-learning content.

The guiding constraint of this codebase: **preserve all original observable behavior and visuals** — copy, animations, interaction details, timings. The README enumerates the exact details to keep (600ms four-color-block loading transition, ash particles, copy tooltip, chat Blob parsing + `': '` split, quiz red/green feedback + localStorage, staggered message/log fade-in, footer & rainbow signature). When adding or changing features, match the surrounding style and do not alter these preserved behaviors unless explicitly asked.

A few deliberate deviations from the original were already made (documented in README): correct `bcrypt.compare` login, parameterized SQL queries, `messages.is_displayed` defaulting to 1, and config externalized to `.env`.

## Commands

This is an **npm workspaces** monorepo; run commands from the repo root.

```bash
npm install              # installs both client and server workspaces

npm run dev              # concurrently starts BOTH (the normal dev loop)
npm run dev:client       # Vite dev server only  → http://localhost:5173/web/
npm run dev:server       # tsx watch (Express + WS) only → http://localhost:3000, ws://localhost:9000

npm run build            # client only: vue-tsc --noEmit (typecheck) && vite build → client/dist
npm start                # server only: tsx src/index.ts (serves client/dist in prod)
npm run preview -w client# preview the built client
```

Dev runs **three services**: Vite (5173, proxies `/api` → Express 3000), Express (3000), and the WebSocket chat server (9000). `npm run dev` starts client + server; the WS server is started by the Express process via `startChatServer()`.

**No test framework or linter is configured** — there are no test/lint scripts. Typechecking the client is done by `npm run build` (`vue-tsc --noEmit`); the server has no separate typecheck step.

### First-time setup
1. Create a MySQL database and import `server/src/schema.sql` (12 tables: `messages`, `devLog`, `users`, `logs`, `blog_posts`, `post_comments`, `post_likes`, `blog_images`, `share_items`, `site_settings`, `tracking_projects`, `tracking_points`).
2. Copy `server/.env.example` → `server/.env` (DB creds, `PORT`, `SESSION_SECRET` (refuses to start in prod without it), `ADMIN_USERNAMES`, `SHARE_MAX_MB`, `BLOG_IMAGE_MAX_MB`, `AVATAR_MAX_MB` (profile avatar cap, default 2), `BANNER_MAX_MB` (profile banner cap, default 4), `ALTCHA_HMAC_KEY` (login captcha signing key; falls back to a per-process random key), `WS_PORT`, and prod `WS_USE_SSL` + cert paths).
3. Copy `client/.env.example` → `client/.env` (`VITE_API_BASE=/api`, `VITE_WS_URL=ws://localhost:9000`). For production, `client/.env.production` points `VITE_WS_URL` at `wss://...` and `server/.env` sets `WS_USE_SSL=true` with cert paths.

## Architecture

### Client (`client/`, ESM, `type: module`)
- **Vue 3 + TS + Vite + Vue Router** SPA. All views are lazy-loaded chunks (`client/src/router/index.ts`); unknown paths redirect to `/`.
- **No Pinia.** "Stores" are plain reactive modules under `client/src/stores/` exposing shared `ref`s via composable-style functions (`useLoading`, `useAuth`, `useLocale`). Auth = server-side session cookie as source of truth + `localStorage` as first-paint cache; `useAuth()` exposes `username`, `isAdmin`, `restored`. `App.vue` calls `initAuth()` on mount (reconciles the cache against `GET /api/auth/me`, clears on 401). The old `/account` route redirects to `/u/me`.
- **Personal profile page** (`/u/:username`, `views/ProfileView.vue`, styles `styles/profile.css` under the `.page-profile` prefix). `/u/me` = current user (guests see a login-guidance state). Visibility of profile fields/content is filtered **server-side** (`GET /api/users/:username/profile`); the view distinguishes self / other / guest plus not-found / disabled / deleted / private states. Self view gains the 设置 tab (privacy toggles, change password, logout, admin reset tool, delete-account danger zone with password + typed-username confirm) and image management: **avatar & banner (壁纸)** share one typed upload flow — pick → client pre-check → **crop** in `components/ImageCropper.vue` (hand-rolled fixed-ratio viewport: avatar 1:1, banner 4:1; drag-to-pan clamped to always-cover, wheel/pinch/button zoom, canvas-cropped JPEG upload ≤512² / ≤1600×400, no upscaling, animated sources become a static frame) → server-side re-encode (avatar 256×256 WebP, banner ≤1600×400 WebP, both via `POST/DELETE /api/auth/avatar|banner` and served from `GET /api/users/avatars/:name`). The banner is a content-column-wide strip (~150px) at the top of the profile header with the avatar straddling its bottom edge — never a full-page background; absent banner keeps the original layout. Blog author names and comment usernames link to `/u/:author`.
- **Loading overlay mechanic** spans three files: `covered` starts `true` (so the overlay covers first paint); `App.vue` calls `loading.reveal()` on mount; the router's `beforeEach` calls `loading.cover()` and waits **`LOADING_COVER_MS` (600ms)** before resolving (skipped on the very first navigation and same-path navigations), `afterEach` reveals. `goExternal(url)` (`stores/loading.ts`) also covers for 600ms before `window.location.href` redirect. The overlay is a four-color-block left-in/right-out animation (redone from the original gray spinner). If you touch navigation or the overlay, preserve this timing.
- **Styles** are global CSS files imported in **both** `main.ts` and `App.vue` (redundant by design — keep both in sync). Each page's CSS is isolated by a page-wrapper class prefix rather than scoped style blocks; when adding page styles, follow the same prefix-isolation convention rather than using `<style scoped>`.
- **Light/dark theme toggle** (`stores/theme.ts`, hand-rolled like the locale store — `useTheme()` → `isDark` / `toggleTheme()`; button `.corner-theme` in the corner nav's right group, sun/moon icon showing the target state, labels `nav.toDark`/`nav.toLight`). Toggling flips a `dark` class on `<html>`; `html.dark` in `design-system.css` overrides the `--ink`/`--paper`/`--gray-*` palette (+ `color-scheme`) so the whole site inverts through the var indirection — **new styles must use the design-system vars, not hardcoded hex**, to stay theme-aware. Resolution order: explicit `localStorage['theme']` > `prefers-color-scheme` (live-follows the system until the user picks manually). An inline script in `index.html` sets the class before first paint (no light-flash on reload — keep it in sync with the store) and maintains `<meta name="theme-color">`; a transient `html.theme-transition` class adds a 200ms color cross-fade (skipped under `prefers-reduced-motion`). Deliberately un-themed: the title card (own dark `--tc-*` cover), `/admin` (own light `--ap-*` system; the ghost corner bar is pinned back to light vars so its icons stay visible on admin's light topbar), `.result-qr-box` (white for QR scanning), question-bank code highlighting (already dark), ash particles (JS assigns black/white inline). `charts_lab.css` carries its warm palette as page-scoped `--lab-*` vars plus a `html.dark` swap block.
- Data access goes through `composables/useApi.ts` (thin `fetch` wrappers — the old PHP endpoints plus the login/blog/share/tracking/admin additions), `composables/useWebSocket.ts` (chat client), `useBlogPosts.ts` + `useMarkdown.ts` (blog, `marked` + DOMPurify), `useAdminApi.ts` (admin panel), `useAshParticles.ts`, `useCopyText.ts`, `useScreenBroadcast.ts` (WebRTC screen broadcast), `useAltcha.ts` (login/signup PoW captcha), `useDataMask.ts` (the client-only data-masking workbench), `useTracking.ts` (value-tracking state + chart data pipeline), and `useSearch.ts` (the site-search dialog's state + local index).
- **Login and signup pages embed an ALTCHA PoW captcha** (the `altcha` npm package, official Web Component; shared logic in `composables/useAltcha.ts`). `<altcha-widget>` is a custom element: keep `isCustomElement` aligned in **both** `client/vite.config.ts` (template compiler) and `client/tsconfig.json` (`vueCompilerOptions`, consumed by `vue-tsc`). `import 'altcha'` and the `altcha/i18n/{zh-cn,en}` packs are imported inside `useAltcha.ts` so the widget lands in a chunk shared by the two auth views (~42KB gzip) and never in the main bundle. The widget pulls challenges from `api.altchaChallengeUrl()` (VITE_API_BASE-prefixed, so it follows the prod `/web/` subpath), reports `{state, payload}` through native `statechange` events (the composable attaches `addEventListener` itself — custom-element events don't flow through Vue template bindings), and is `.reset()` after any failed submit because solutions are single-use server-side. Language binds reactively to the site locale (zh → `zh-cn`). Theming happens only via `--altcha-*` custom properties on the host (in `login.css`, shared by both `.page-auth` pages) — the widget's shadow DOM is closed.
- **Data masking page** (`/data-mask`, `views/DataMaskView.vue` + `composables/useDataMask.ts`, styles `data_mask.css` under `.page-data-mask`) — **client-only** Excel/CSV masking, no backend. Files live in memory only (extension + ≤10MB local pre-check; zero upload, zero localStorage/IndexedDB). Grid preview (50-row cap, own scroll box), header-click multi-column select + row checkboxes to scope rules. 8 rule types stack per sheet: mask keep-ends, fixed value, deterministic saltable hash pseudonym (same input → same 12-hex), value-seeded fake data (name/phone/email/18-digit ID with valid checksum; the seed is rule id + column + value, so equal values map consistently within one column under one rule — the hash is the globally consistent one), numeric bucketize or ±k% jitter, date generalization, regex replace, nullify; empty cells skipped, rules removable/reset, changed cells highlight + optional original-comparison mode. Exports are local Blobs: hand-serialized CSV (BOM+CRLF, active sheet) and xlsx built by cloning the workbook (`markRaw` — reactive proxies break `structuredClone`) and swapping only changed cells in place on every sheet. SheetJS `xlsx@^0.18.5` (the only new dep) is dynamically imported inside the composable so it never enters the main bundle.
- **Site-wide search** (Ctrl+K / Cmd+K, or the `.corner-search` magnifier chip in the corner nav's right group). `components/SearchDialog.vue` is mounted at App level **outside `RouterView`** (same fixed-position rule as the corner nav); state + index live in `composables/useSearch.ts` (module singleton). Search is **hybrid**: the client-side index covers static posts (full markdown body via `getAllPosts()`), question-bank localStorage (`questions` / `questions:<username>`, same key rule as the view), ChartsLab cases (data extracted to `content/chartsLabCases.ts`, shared with the view) and page quick-links (zh/en keywords); DB content (user-post bodies w/ LOCATE snippet, comments on published posts, devlog, visible messages, privacy-allowed users) comes from `GET /api/search?q=` — 200ms debounce, `AbortController` + seq guard against stale responses. Results render grouped (博客/评论/题库/图表/开发日志/留言板/用户) with ink-inverted `<mark>` highlights; empty query shows a quick-links grid, zero results an empty state + quick links, fewer than 3 content results appends a 相关页面 fallback group; a server failure degrades to local-only results with a notice. Keyboard: ↑/↓ navigate, Enter opens (`router.push`, normal 600ms cover), Esc closes and refocuses the trigger; IME composition keys are ignored; Ctrl+K is ignored while the title card is up. The **search scope is soft-coded per module** (8 toggles: 5 server + 3 client) stored in `site_settings` (`search_scope` JSON), editable in the admin panel's 搜索设置 tab (`GET/PUT /api/admin/search-config`) and served publicly via `GET /api/search/config` (60s cache; missing row/bad JSON → all-on defaults). Styles: `styles/search.css` (`.search-*`, mask z-index 9000 — above the corner nav, below tooltips), imported in both `main.ts` and `App.vue`; i18n `search.*` + `nav.search` in zh/en. Share items and chat logs are deliberately **not** searchable (pickup codes are secrets; chat logs are admin-only).
- **Value tracking page** (`/tracking`, `views/TrackingView.vue` + `composables/useTracking.ts`, styles `styles/tracking.css` under `.page-tracking`) — multi-project numeric tracking with **two hand-rolled SVG line-chart renderers, zero chart libraries**: `components/tracking/InkLineChart.vue` (墨线 — lieflat Mono grammar ported from the charts-lab hairline-line exhibit: card four-piece structure with auto conclusion title, grayscale ladder for ≤6 series by importance, hairline 1px paths with draw/pop/fade entrance, per-point dots that auto-hide past 60 points, hollow weekend dots, top-peak halo labels, calendar barcode floor, fixed warm-paper palette in **both** themes like a picture) and `components/tracking/ScienceLineChart.vue` (科研 — journal-figure grammar: boxed axes with inward major/minor ticks, solid/dotted grid, Okabe-Ito colorblind-safe palette honoring per-project custom colors, marker-shape rotation ○□△◇✕, framed legend with optional R², moving-average dashes + ±1σ band + optional regression trend line, crosshair readout with nearest-x snapping, light/dark non-data palettes, no entrance animation). Both consume one shared props contract (`{frame, config, isDark}`) and one data pipeline in `useTracking.ts` (range filter → day/week/month bucket aggregation × avg/min/max/last → stats → trailing moving average + rolling σ → min-max/z-score normalization → regression), render all styling as **SVG attributes** (not CSS vars) so PNG serialization keeps colors, and mark hover layers `data-hover-layer` for export exclusion. Config (style toggle, title, range, aggregation, smoothing, normalization, y-axis, per-series visibility, style-specific toggles) persists in `localStorage['trackingConfig']` (enum whitelisted on load). Data lives server-side per user (see `/api/tracking`); guests get a deterministic demo dataset (3 projects × 90 days, charts-lab `rnd` idiom) with read-only data management. Stats summary cards (latest/mean/range/Δ/R²) sit above the chart; CSV export (union-aligned timestamps + MA columns, BOM+CRLF) and PNG snapshot export (clone → strip classes/hover → blob → 2x canvas; CSP `img-src blob:` already allows) are local Blob downloads. Chart SVGs carry an explicit full-canvas background rect so exports aren't transparent.

### Server (`server/`, ESM, `type: module`, runs TS directly via `tsx` — **no compile step**)
- **Express + mysql2 (promise pool) + express-session (MySQL store on the shared pool) + bcryptjs + ws.** Entry: `src/index.ts` mounts the `/api/messages`, `/api/devlog`, `/api/auth`, `/api/blog`, `/api/share`, `/api/search`, `/api/tracking` and `/api/admin` routers (plus a `/api/health` probe), configures sessions, then in production statically serves `client/dist` with an SPA fallback (`GET *` returns `index.html` unless the path starts with `/api`).
- **Import paths use `.js` extensions** even though sources are `.ts` (ESM + Bundler resolution). When adding modules, import from `'./foo.js'` and define route modules as Express `Router`s in `src/routes/`.
- **DB**: shared `mysql2/promise` pool in `src/db.ts` (creds from `.env`, never hardcoded). Always use **parameterized queries** (`pool.query(sql, [params])`) — this was a deliberate fix over the original string-concatenation PHP.
- **API surface** (old PHP endpoints + login/blog/share/admin additions; REST errors are machine codes `{ error: 'CODE' }`, not prose):
  - `GET/POST /api/messages` — board; GET filters `is_displayed = 1`, orders by `id DESC`, takes `?limit` (1–1000, default 500; admins see all rows incl. `id`/`is_displayed`); POST inserts with `NOW()` and relies on the column default of 1 for `is_displayed` (do **not** write that column on insert, or messages won't display). `PATCH /api/messages/:id` (`{is_displayed: 0|1}`) is admin-only moderation.
  - `GET/POST /api/devlog` — dev log; GET takes the same `?limit`; POST writes only `change_description` (timestamp is DB-generated) and is admin-only (401 not logged in / 403 not whitelisted).
  - `POST /api/auth/signup`, `POST /api/auth/login` — `bcrypt.hash` on signup (salt rounds 10), `bcrypt.compare` on login (the original used plaintext compare and was broken). `ER_DUP_ENTRY` → 400 `{ error: 'AUTH_USERNAME_EXISTS' }`. On success, login regenerates the session, sets `req.session.username` and responds `{username, isAdmin}`; disabled accounts (`users.status='disabled'`) are rejected with `AUTH_ACCOUNT_DISABLED`. Plus `GET /api/auth/me` (session check + account-status re-verification — disabled/deleted sessions get destroyed here), `POST /api/auth/logout`, `POST /api/auth/change-password`, `POST /api/auth/ws-token` (one-time WS handshake token, active-status checked), `POST /api/auth/admin/reset-password` (admin-only, cannot reset self). Profile additions: `PUT /api/auth/profile` (displayName/bio/region/socialLinks — urls must be http(s)://), `PUT /api/auth/privacy` (five boolean flags), `POST /api/auth/avatar|banner` + `DELETE /api/auth/avatar|banner` (multipart uploads sharing one validation chain — multer ≤`AVATAR_MAX_MB` default 2 / ≤`BANNER_MAX_MB` default 4 → mime whitelist → extension → magic sniff; avatars re-encoded to 256×256 WebP, banners to ≤1600×400 WebP), `POST /api/auth/delete-account` (password + typed username; cascades the user's posts/comments/likes/blog-images/shares + disk files and both user-image files, anonymizes the `users` row). Public profile data: `GET /api/users/:username/profile` (privacy-filtered server-side; 404/410/403 states), `GET /api/users/:username/posts|comments` (paged content tabs), `GET /api/users/avatars/:name` (public WebP user-image file — avatars and banners share the dir, name pattern and route).
  - `GET /api/auth/altcha-challenge`, and the `altcha` field on **both** auth posts — **ALTCHA PoW captcha** (`server/src/altcha.ts` on `altcha/lib`): the public challenge endpoint (rate-limited 30/min/IP, `no-store`) issues a signed PBKDF2/SHA-256 challenge (cost 5000, keyPrefix "00", 120s expiry; browser solve ≈0.5s via the widget's workers, server verify <1ms). `POST /api/auth/login` and `POST /api/auth/signup` verify the base64 `altcha` payload **before** the credential lookup / user insert and reject with `AUTH_CAPTCHA_REQUIRED|INVALID|EXPIRED`; solutions are single-use (verified nonces burned in an in-memory replay map — a wrong password or duplicate username still consumes the captcha, and the client resets the widget for the next attempt). HMAC key: `ALTCHA_HMAC_KEY` (falls back to a per-process random key with a prod warning). Two compat notes: the lib uses the WebCrypto global (Node 18 ships it; `altcha.ts` guards with `node:crypto`.webcrypto), and the widget's blob-URL workers require `worker-src 'self' blob:` in the CSP (`securityHeaders.ts`) — without it the auth pages break **only in production** (dev pages are served by Vite, which sends no CSP).
  - `GET/POST /api/blog`, `GET/PUT/DELETE /api/blog/:id`, `GET/POST /api/blog/:slug/comments`, `GET/POST /api/blog/:slug/likes` — user-authored posts (slug namespaced `u-*`), slug-keyed comments/likes (static `.md` posts get them too); author-or-admin on writes, drafts author-visible only. Compose-side extras: `POST /api/blog/images` (login, multipart, rate-limited; magic-byte sniff + mime/extension whitelist, SVG rejected, `BLOG_IMAGE_MAX_MB` default 8, per-user quota 500, files in `server/uploads/blog`, tracked in `blog_images`). Each upload also gets a **WebP display variant** via `sharp` (≤1600×4000, q82; skipped for small/unsrinkable images; failures fall back to original-only): `GET /api/blog/images/:name` serves the variant, `…/original` the original, `…/meta` `{origSize, dispSize}`. The compose page inserts `![caption](url)` and renders standalone images as `<figure>` + `<figcaption>`, with `enhanceBlogImages()` adding a size badge + 查看原图 link on the reading page; the 导入 .md button is a client-side-only import (no server round trip). Admin cleanup `POST /api/admin/images/cleanup` purges unreferenced images (both files). `sharp` is pinned `^0.34` in `server/package.json` — 0.35+ requires Node ≥ 20 and crash-looped the Node 18 production host (fixed by downgrade); don't bump it without raising Node first.
  - `POST /api/share/text|file`, `GET /api/share/:code` (+ `/file`, `/download`) — QR-code share (text/image/file with expiry + pickup code); `GET /api/share/mine` and `DELETE /api/share/:code` (owner or admin) are the login-adapted endpoints.
  - `GET /api/search?q=` — **site-wide search** (Ctrl+K dialog; rate-limited 60/min/IP, `q` trimmed 1–100 chars else `400 SEARCH_QUERY_INVALID`). Runs escaped-LIKE queries (the admin router's `likePattern`, now exported) per **enabled scope module** in parallel: user posts (published only, body matches get a `LOCATE`-based snippet), comments on published/static posts (LEFT JOIN `blog_posts`, drafts excluded), devlog, visible messages (`is_displayed=1`), and users gated `status='active' AND is_profile_public=1 AND allow_index=1` (users opt out via their privacy settings). Responds `{query, modules, posts, comments, devlogs, messages, users}` (`no-store`, per-module LIMITs 5–8). `GET /api/search/config` publicly serves the module toggles (60s cache). Scope is stored as JSON in the `site_settings` table (key `search_scope`; helpers in `src/searchConfig.ts`), written via `GET/PUT /api/admin/search-config` (admin-only; PUT validates all-boolean known keys else `400 SEARCH_CONFIG_INVALID`). Share items and chat logs are not searched by design.
  - `/api/tracking/*` — **value tracking** (`src/routes/tracking.ts`; login required on every endpoint, ownership by `owner_username` with **no admin override** — the data is strictly personal and has no admin-panel surface). `GET /projects` lists own projects with aggregate stats (pointCount/latest/latestAt/min/max via correlated subqueries; note the `\`minValue\`/\`maxValue\`` aliases are backtick-quoted — MINVALUE/MAXVALUE are MySQL 8 reserved words); `POST /projects` (name 1–40, unit ≤20, description ≤200, color `#rrggbb` or null; 50-project cap, 20/10min); `PUT/DELETE /projects/:id` (delete cascades its points manually — no FKs); `GET /projects/:id/points?limit(1–5000)` returns `recorded_at`-ascending points; `POST /projects/:id/points` (value finite |v|<1e11 rounded to 4dp, `recordedAt` 'YYYY-MM-DD[ HH:mm[:ss]]' defaulting to NOW() via `IFNULL(?, NOW())`, 10000-point cap, 60/10min); `PUT/DELETE /points/:id` edits/removes a point through parent-project ownership. `recorded_at` is stored verbatim (client local time, no timezone conversion) and returned as 'YYYY-MM-DDTHH:mm:ss'. Error codes `TRACKING_*` map to i18n `api.*` entries.
- **WebSocket chat** (`src/ws/chatServer.ts`) is a **separate `ws` server** on its own port (9000 dev / `wss`+SSL in prod), independent from Express. Logged-in users connect with `?token=` (one-time token from `POST /api/auth/ws-token`) and are shown/keyed as `@username`; guests stay IP-keyed (same IP overwrites the previous connection). Chat broadcasts ride the same `RTC:` JSON channel as the signaling — `{t:'chat', from, u?, av?, msg}` (registered users carry `u`=username + `av`=avatar filename, queried once per connection; the `welcome` frame carries the user's own `av` for local echo; guests send only `from`=IP) — to everyone *except* the sender; plain-text `name: message` remains only as the client's parse-failure fallback. Connect/disconnect/message events still log to the `logs` table as plain text (sender = username or IP). WebRTC screen-broadcast signaling rides the same server via `RTC:`-prefixed frames (single live room, first-come-first-served; not broadcast, not logged). Chat↔profile linkage: the chat page renders registered senders' avatar (or initial circle) + name as a RouterLink to `/u/:username` (`MessageCard.vue` optional `identity` prop; the home message board doesn't pass it).

### Cross-cutting notes
- The **server** and **client** communicate three ways: REST (`/api/*`, same-origin via Vite proxy in dev, direct in prod), WebSocket (separate port, URL from `VITE_WS_URL`), and the session cookie (login). Keep these three channels distinct — auth lives in the cookie, not a token the client sends.
- `mysql2`, `express`, `vue`, etc. are listed in the respective workspace `package.json` files; install at the **root** so npm workspaces links them correctly.
- The repo is a single git history ("Initial commit: Vue 3 + TypeScript 全栈个人网站"). `devlogs/` and `logs/` are gitignored local-only notes.
