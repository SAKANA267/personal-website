把一套跑了多年的 PHP + 原生 JS 留言板搬到 Vue 3 + TypeScript，听起来像「重写」，但真正的约束恰恰相反：**不破坏任何肉眼可见的细节**。提交后的提示文案、时间戳的格式、卡片淡入的先后顺序——这些是老站的气质，搬过去就变味了。

## 目标：忠实搬运，而非重新设计

重构的第一条原则是「可观察行为不变」。用户感知到的东西，包括 1000 毫秒的加载过渡、灰烬粒子、留言卡片的淡入节奏，都要一比一保留。技术栈换了，灵魂不能换。

> 极简不是少做事，而是把每一格间距、每一道发丝线都调到刚好。

## 关键的几处搬运

落到代码上，有几处细节最值得记下：

- **时间戳格式**：原站用 `Y-m-d H:i:s`，新站也用同一格式，只是从 PHP 换成了 JS 的 `Date`。
- **卡片淡入顺序**：留言按时间倒序，最新的在前，淡入延迟随索引递增，让视线自然落在最新一条。
- **提交提示**：用复刻的 `copy tooltip`，而不是浏览器原生弹窗。

### 一段最朴素的拉取

留言列表的获取，最终就是一个薄薄的 `fetch` 包装，对应原来的 PHP 接口：

```ts
async function getJson<T>(path: string): Promise<T> {
  const res = await fetch(`${BASE}${path}`)
  return res.json()
}
```

没有状态库、没有复杂封装，够用就好。新站也刻意没上 Pinia——「store」就是几个暴露 `ref` 的普通模块。

## 没做的事

同样重要的是**没做什么**：

1. 没换配色，仍是 `#fafafa` 的纸色配 `#0a0a0a` 的墨色。
2. 没加渐变、撞色，层次全靠六层灰度。
3. 没改留言的 Blob 解析与 `': '` 分割——这是老协议的一部分。

---

重构的终点，是让访客察觉不到重构发生过。代码变了，页面没变，任务就算完成。
