# AGENTS.md

Workspace guidance for ZCode agents working in this repo. A more detailed narrative lives in `CLAUDE.md` and `README.md` — read those before touching sensitive areas (loading overlay, navigation, chat, preserved visuals).

## What this is

SAKANA's personal website, **faithfully ported** from raw HTML/CSS/JS + PHP/MySQL + Node WebSocket to **Vue 3 + TypeScript SPA + Node/Express + MySQL + ws**. Sections: home, online chat, question bank, dev log, blog, share, login/signup, data masking, value tracking, site-wide search.

**Governing constraint:** preserve all original observable behavior and visuals — copy, animations, interaction details, timings (see README's enumerated list). Match surrounding style; do not alter preserved behaviors unless explicitly asked. A few deliberate deviations are documented in README (correct `bcrypt.compare`, parameterized SQL, `messages.is_displayed` default 1, config externalized to `.env`).

## Layout

```
package.json        # npm workspaces root; concurrently runs client + server
client/             # Vue 3 + TS + Vite + Vue Router SPA (ESM)
server/             # Node + Express + mysql2 + ws, runs TS directly via tsx (ESM, no compile step)
deploy/             # bash deploy script + PM2 ecosystem + remote-setup
devlogs/ logs/      # gitignored local-only notes
```

## Commands (run from repo root)

```bash
npm install            # installs both workspaces (install at root so workspaces link)
npm run dev            # concurrently: Vite (5173) + Express/WS (3000, ws 9000)
npm run dev:client     # Vite only
npm run dev:server     # tsx watch, Express + WS only
npm run build          # client only: vue-tsc --noEmit (the only typecheck) && vite build → client/dist
npm start              # server only: tsx src/index.ts (serves client/dist in prod)
npm run deploy         # bash deploy/deploy.sh (needs deploy/.deploy.env)
```

**No test framework, no linter.** The only typecheck is `vue-tsc --noEmit` inside `npm run build` (client). The server has no typecheck step.

## Dev runtime

Three services: Vite (5173, **`base: '/web/'`** so dev URL is `http://localhost:5173/web/`, proxies `/api` → Express 3000), Express (3000), WebSocket chat (9000, started by Express via `startChatServer()`).

Production serves under nginx subpath `/web/` (nginx strips the prefix before proxying to Node). `client/.env.production` sets `VITE_API_BASE=/web/api` and `VITE_WS_URL=wss://...`; `server/.env` sets `WS_USE_SSL=true` + cert paths for `wss`.

- **Styles** are global CSS files imported in **both** `main.ts` and `App.vue` (redundant by design — keep both in sync). Page CSS is isolated by page-wrapper class prefix, **not** `<style scoped>`. Follow the prefix convention for new pages.
- **Responsive pattern (all pages, desktop-first, layout-preserving).** Baseline lives in `design-system.css` §7 "响应式基线"; per-page overrides sit in each page CSS's `响应式设计` section. Rules:
  1. **Breakpoints: 1024 / 768 / 480 px**, max-width queries in that order. 1024 = wide furniture退场 (e.g. blog TOC hidden); 768 = tablet single-column, `--container-padding` steps 24→16; 480 = phone compact, padding 16→12. Don't invent new breakpoints.
  2. **No horizontal page overflow, ever** — fix the root cause, never `overflow-x: hidden` on body. The global baseline guarantees: `img/svg/video/canvas/iframe { max-width: 100% }`, `textarea { max-width: 100% }`, and `:not(pre) > code|kbd|samp { overflow-wrap: anywhere }` (inline code like `` `{...}` `` tokens may wrap; `pre > code` keeps horizontal scrolling).
  3. **Wide content scrolls inside its own box, it never stretches the page.** Template-owned tables/wide blocks get wrapped in the shared `.table-scroll` utility (`overflow-x: auto`; used by DevLog's `#userTable` — its ≤480px `min-width: 500px` depends on this wrapper). v-html markdown tables can't be wrapped, so `.markdown-body table { display: block; overflow-x: auto }` at ≤768 (both blog-detail and compose-preview scopes). Fenced code blocks scroll via `pre { overflow-x: auto }`.
  4. **Flow first: flex rows that can collide get `flex-wrap: wrap`** (`.compose-actions`, meta strips already do); grids use `auto-fit` + `minmax()` or collapse to `1fr` at 768.
  5. **Fluid heights use `dvh` with a `vh` fallback** (`height: 100vh; height: 100dvh;`) — title card cover, loading overlay — so mobile URL-bar resizing can't trap content. iframe scrolling is CSS-controlled (`overflow: hidden` desktop / `auto` ≤768 in charts_lab), the deprecated `scrolling=""` attribute is not used.
  6. Fixed-position tooltips clamp with `max-width: calc(100vw - …)` at ≤480 so they can't hang off-screen.

## Server rules

- **REST errors are machine codes, not prose:** every `4xx/5xx` JSON returns `{ error: 'CODE' }` (SCREAMING_SNAKE, e.g. `AUTH_INVALID_CREDENTIALS`, `SHARE_FILE_TOO_LARGE` + sibling params like `maxMb`/`min` where needed). The client maps them to localized text via the `api.*` i18n keys (`apiError()` in `stores/locale.ts`); unknown strings pass through verbatim. Don't put sentences in `error` fields. Legacy exceptions kept on purpose: `GET/POST /api/messages` and `GET /api/devlog` still return 200-with-`{error: e.message}` on DB failure (original PHP shape).
- **Express + mysql2/promise pool + express-session (MySQLStore on the shared pool, auto-creates `sessions` table) + bcryptjs + ws.** Entry `src/index.ts` mounts routers under `/api`, configures sessions, and in prod statically serves `client/dist` with SPA fallback (`GET *` → `index.html` unless path starts with `/api`).
- **Import paths use `.js` extensions** even though sources are `.ts` (ESM + Bundler resolution). Add modules as Express `Router`s in `src/routes/`.
- **Admin whitelist:** `server/src/admin.ts` — `sessionUsername(req)` / `isAdmin(req)`; admins = comma-separated `ADMIN_USERNAMES` in `.env` (unset → nobody is admin). Gates devlog writes, message moderation, share deletion.
- **Admin panel API** (`src/routes/admin.ts`, mounted at `/api/admin`, router-level middleware 401s the logged-out and 403s non-admins on **every** endpoint): `GET /overview` (counts across all 9 tables + hidden/draft/active breakdowns + 5 latest messages + 5 latest chat logs + server uptime/node/now, single round trip); `GET /messages|/devlog|/posts|/comments|/shares|/users|/logs` — paged lists (`?page&pageSize(10-100,def 20)&q`, q does escaped `LIKE` with `ESCAPE '\\'`; all include hidden rows/drafts; `id DESC`, posts by `date DESC,id DESC`; shares omit `content`, users carry posts/comments/likes/shares subselect counts); `PATCH /posts/:id/publish` (`{is_published:0|1}` quick toggle without full PUT); `POST /shares/cleanup` (purge expired share rows + their disk files); `POST /images/cleanup` (purge `blog_images` rows + disk files not referenced by any `blog_posts.body`); `GET/PUT /search-config` (read/save the site-search scope toggles — GET is `no-store` for the panel, PUT validates boolean known keys, storage via `src/searchConfig.ts` into `site_settings`). List shape is `{ rows, total, page, pageSize }`.
- **WS one-time tokens:** `server/src/wsTokens.ts` — `POST /api/auth/ws-token` issues a 60s single-use token (session required); the WS handshake URL `?token=` consumes it in-process to attach a username to the chat connection.
- **ALTCHA captcha (login + signup):** `server/src/altcha.ts` — challenge issuance/verification on top of `altcha/lib` (`createChallenge`/`verifySolution` + `pbkdf2.deriveKey`), shared by both auth endpoints. Params: PBKDF2/SHA-256, cost 5000, keyPrefix "00" (~256 solver attempts), 120s expiry; browser solve ≈0.5s, server verify <1ms. HMAC key = `ALTCHA_HMAC_KEY` in `.env`, falling back to a per-process random key (startup warning in prod; only in-flight challenges die on restart). Solutions are **single-use**: verified nonces are burned in an in-memory map (replay → `AUTH_CAPTCHA_INVALID`); failed submits (wrong password, duplicate username) consume the captcha too, so the client must re-solve. The lib needs the WebCrypto global — Node 18 ships it (experimental); `altcha.ts` assigns `node:crypto`.webcrypto as a guard for older/quieter runs. The widget's blob-URL PoW workers require the CSP's `worker-src 'self' blob:` (`securityHeaders.ts`) — dropping that directive breaks auth pages in prod only (dev pages come from Vite without CSP).
- **DB:** shared `mysql2/promise` pool in `src/db.ts`, creds from `.env` (never hardcoded). Always **parameterized queries** (`pool.query(sql, [params])`).
- **Schema** (`server/src/schema.sql`, 12 tables): `messages`, `devLog`, `users`, `logs`, `blog_posts`, `post_comments`, `post_likes`, `blog_images`, `share_items`, `site_settings` (generic k/v settings table; currently only `search_scope` for the site-search module toggles), `tracking_projects`, `tracking_points` (value tracking). Existing deployments upgrading to blog login-integration need the `blog_posts` ALTERs (slug/author_username/body/updated_at) + the two comment/like tables — noted in schema.sql; the blog-image feature adds the `blog_images` table (same file's migration note); share ownership ALTER is historical; **the profile feature adds 13 columns to `users`** (display_name/avatar/bio/region/social_links + 5 privacy flags + status + created_at — ALTER block in the same migration note) **plus `banner`** (the banner column, its own ALTER note); **site search adds the `site_settings` table** (its own CREATE in the same migration note — row not pre-seated, defaults live in `server/src/searchConfig.ts`); **value tracking adds the two `tracking_*` tables** (their own CREATE in the migration note).
- API surface (old PHP endpoints + login-adaptation additions):
  - `GET/POST /api/messages` — board. GET filters `is_displayed = 1`, orders `id DESC`, takes `?limit` (1-1000, default 500; admins see all rows incl. `id`/`is_displayed`). **Do not write `is_displayed` on insert** — it relies on the column default 1 or messages won't display. `PATCH /api/messages/:id` (`{is_displayed: 0|1}`) is admin-only moderation.
  - `GET/POST /api/devlog` — GET takes the same `?limit`; POST writes only `change_description` (timestamp is DB-generated) and is **admin-only** (401 not logged in / 403 not whitelisted).
  - `GET /api/blog` — user posts (`author_username IS NOT NULL`): published for everyone + own drafts when logged in, `date DESC`. Field aliases must match frontend `BlogPost` verbatim (`read_time AS readTime`, `author_username AS author`). `GET /api/blog/:slug` — single DB post incl. `body` (drafts: author/admin only, else 404). `POST /api/blog` (login) creates; server derives `slug` (`u-` namespace), `excerpt`, `read_time`, `date`. `PUT/DELETE /api/blog/:id` — author or admin (403 otherwise); delete cascades `post_comments`/`post_likes` by slug. `GET/POST /api/blog/:slug/comments` — list public / post login (1-2000 chars, drafts 404). `DELETE /api/blog/comments/:id` — comment author or admin. `GET/POST /api/blog/:slug/likes` — `{count, liked}` / login toggle (UNIQUE guarantees one per user). Static `.md` posts have no DB rows; comments/likes keyed by slug still work for them.
  - `POST /api/blog/images` (login, multipart field `file`, rate-limited 20/10min/user) — blog-image upload. Security chain: multer size limit (`BLOG_IMAGE_MAX_MB`, default 8, nginx `client_max_body_size` must be ≥) → declared-mime whitelist (PNG/JPEG/GIF/WebP/BMP/AVIF; **SVG always rejected** — inline SVG = same-origin XSS) → raw-extension consistency → per-user quota (500) → **magic-byte sniff must match the declared type** (renamed/polyglot files → `BLOG_IMAGE_MALFORMED`, temp file unlinked). Originals land in `server/uploads/blog/<32-hex><canonical-ext>` + a WebP display variant `<hex>.disp.webp` (sharp, ≤1600×4000 q82, animated kept; skipped for small/unsrinkable images), both tracked in `blog_images`. `GET /api/blog/images/:name` — public, serves the display variant (falls back to original); `…/:name/original` — original bytes; `…/:name/meta` — `{origSize, dispSize}` for the reading-page badge. All inline with whitelisted Content-Type + `immutable` cache. `DELETE /api/blog/images/:name` — uploader or admin; removes both files (compose-cancel uses it to avoid orphans).
  - `POST /api/auth/signup|login` — `bcrypt.hash` (salt 10, signup enforces password ≥ 6 chars) / `bcrypt.compare`. `ER_DUP_ENTRY` → 400. On success set `req.session.username`; login responds `{username, isAdmin}`. **Both additionally require a valid `altcha` payload field** (PoW verification happens before the credential lookup / user insert; errors `AUTH_CAPTCHA_REQUIRED|INVALID|EXPIRED`; see the ALTCHA bullet above).
  - `GET /api/auth/altcha-challenge` — public, rate-limited 30/min/IP, `no-store`; returns a signed ALTCHA challenge JSON (see `server/src/altcha.ts`).
  - `GET /api/auth/me` — session check → `{username, isAdmin}` or 401 (**also re-verifies `users.status`** — a disabled/deleted account's live session is destroyed here, kicking the user out on next boot). `POST /api/auth/logout` — destroys session + cookie. `POST /api/auth/change-password` — logged-in + old-password check. `POST /api/auth/ws-token` — one-time WS handshake token (same active-status check). `POST /api/auth/admin/reset-password` — admin-only reset (login + whitelist, cannot reset self, target user must exist).
  - **Profile endpoints (个人主页).** `GET /api/users/:username/profile` — public profile, **privacy-filtered server-side** (region/social/content dropped per the user's flags for non-self/non-admin viewers; `404 USER_NOT_FOUND` / `410 USER_DELETED` / `403 USER_DISABLED` / `403 PROFILE_PRIVATE`); includes stats (posts/comments/likes-received; posts count includes drafts only for self/admin). `GET /api/users/:username/posts|/comments` — paged `{rows,total,page,pageSize}` content tabs (posts reuse blog.ts's exported `POST_FIELDS`+`normalizeRow`; others see published only and are gated by `is_profile_public`+`show_content`). `GET /api/users/avatars/:name` — public WebP user-image file (`<32hex>.webp` name whitelist, immutable cache; route registered **after** the `/:username/*` routes so a user literally named "avatars" still resolves). `PUT /api/auth/profile` — edit own profile (displayName ≤40 / bio ≤500 / region ≤60 / socialLinks ≤5, urls must be `http(s)://` — blocks `javascript:`). `PUT /api/auth/privacy` — the five boolean flags, saved verbatim. `POST /api/auth/avatar|banner` — multipart uploads sharing one validation chain (multer size ≤`AVATAR_MAX_MB` default 2 / ≤`BANNER_MAX_MB` default 4 → mime whitelist → extension → magic sniff, SVG rejected); avatars re-encode via sharp to 256×256 center-crop WebP, banners to ≤1600×400 `fit:inside` WebP (GIF/WebP animated kept; both land in `server/uploads/avatars/<32hex>.webp` served by the same avatars route); each replaces its column and unlinks the old file. `DELETE /api/auth/avatar|banner` — nulls the column, unlinks the file. `POST /api/auth/delete-account` — password verify + `confirm === username`, then cascades: own posts (with their comments/likes), own comments/likes, own `blog_images` + files, own `share_items` + files, and anonymizes the `users` row (`status='deleted'`, password scrambled, profile fields NULL, avatar + banner files removed); message-board entries and chat logs are site records and stay. Session destroyed.
  - `GET /api/share/mine` (logged-in, own uploads) and `DELETE /api/share/:code` (owner or admin; `/mine` must stay registered before `/:code`) are login-adaptation additions; text/file uploads record `uploader_user` when logged in.
  - `GET /api/search?q=` — **site-wide search** for the Ctrl+K dialog (rate-limited 60/min/IP; `q` trimmed 1–100 chars else `400 SEARCH_QUERY_INVALID`). Escaped-LIKE queries (the admin router's `likePattern`, now exported from `routes/admin.ts`) run per enabled scope module in parallel: published user posts (body hits get a `LOCATE`-based snippet), comments on published/static posts (LEFT JOIN — comments on drafts excluded), devlog, `is_displayed=1` messages, and users gated `status='active' AND is_profile_public=1 AND allow_index=1`. Responds `{query, modules, posts, comments, devlogs, messages, users}` (`no-store`, per-module LIMIT 5–8). `GET /api/search/config` publicly serves the module toggles (`Cache-Control: max-age=60`); scope JSON is stored in `site_settings` via helpers in `server/src/searchConfig.ts` (missing/broken row → all-on defaults) and written by `GET/PUT /api/admin/search-config` (admin-only; PUT rejects unknown/non-boolean keys with `400 SEARCH_CONFIG_INVALID`). Share items and chat logs are not searchable by design.
  - `/api/tracking/*` — **value tracking** (`src/routes/tracking.ts`; every endpoint requires login, ownership by `owner_username` with **no admin override** — strictly personal, no admin-panel surface). `GET /projects` (own list + aggregate stats — the minValue/maxValue aliases are backtick-quoted because MINVALUE/MAXVALUE are MySQL 8 reserved words), `POST /projects` (name 1-40 / unit ≤20 / desc ≤200 / color #rrggbb or null; 50-project cap; 20/10min), `PUT/DELETE /projects/:id` (delete cascades points manually), `GET /projects/:id/points?limit(1-5000)` (recorded_at ASC), `POST /projects/:id/points` (finite |v|<1e11 rounded 4dp; recordedAt 'YYYY-MM-DD[ HH:mm[:ss]]' defaulting to NOW() via IFNULL; 10000-point cap; 60/10min), `POST /projects/:id/points/batch` (Excel batch import — body `{points:[…]}` reusing the single-point validator; 1–1000 rows per request (`TRACKING_BATCH_EMPTY`/`TRACKING_BATCH_TOO_LARGE`+`max`), first invalid row reported as `{error, index}`, 10000-point cap checked before write, committed as **one multi-row INSERT = atomic per request**; limiter of its own at 20/10min; responds `{inserted}` — the client chunks larger files), `PUT/DELETE /points/:id`. recorded_at stores the client's local time verbatim (no tz conversion) and returns as 'YYYY-MM-DDTHH:mm:ss'. Error codes `TRACKING_*`.
- **WebSocket chat** (`src/ws/chatServer.ts`): separate `ws` server on its own port (9000 / `wss`+SSL), independent of Express. Identity: logged-in users connect with `?token=` (consumed via `wsTokens`) and are shown/keyed as `@username`; guests stay IP-keyed (same IP overwrites). Chat broadcasts now ride the same `RTC:` JSON channel as signaling — frame `{t:'chat', from: display, u?, av?, msg}` (registered users carry `u`=username + `av`=avatar filename, looked up once per connection; guests only `from`=IP), sent to everyone *except* the sender; this also keeps message text containing `': '` intact (the legacy plain-text `name: message` split survives client-side only as the parse-failure fallback). Connect/disconnect/message still log to `logs` as plain text (sender = username or IP). Screen broadcast (WebRTC) signaling rides the same server as `RTC:`-prefixed frames (single live room, first-come-first-served; not broadcast, not logged); the `welcome` frame additionally carries the connecting user's own `av` for local echo. **Chat↔profile linkage:** the client renders registered senders' avatar (image, or username-initial circle when no custom avatar) + name in `MessageCard.vue` as one RouterLink to `/u/:username` (optional `identity` prop — the home message board doesn't pass it and renders unchanged); guests keep the plain-text sender look.

## Cross-cutting

- Three client↔server channels stay distinct: REST `/api/*` (same-origin via Vite proxy in dev, direct in prod), WebSocket (separate port, URL from `VITE_WS_URL`), and the session cookie (auth lives in the cookie, not a client-sent token).
- `deploy/.deploy.env` (gitignored) holds SSH host/user/dir/PM2 app; deploy script strips CRLF from those values to survive Windows editing.
- `.env`, certs (`*.pem`/`*.key`, `server/certs/`), `logs/`, `devlogs/`, and `deploy/.deploy.env` are gitignored — never commit secrets.
